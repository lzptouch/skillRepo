# 测试数据构造清单

> 只用 happy path 跑通，等于没测。AI 生成的模块通常只在它被生成的那一个上下文里跑过一次——边界、脏数据、失败全是空白。
> 下面五类，缺一类就不算跑通。

## 1. 正常（happy）

- [ ] 典型输入
- [ ] 常见规模的数据量
- [ ] 最常用的参数组合

`fixtures/happy.json`

## 2. 边界（edge）

- [ ] 空值 / null / undefined
- [ ] 空数组、空字符串
- [ ] 0、负数、最大值、最大值 ±1
- [ ] 超长字符串（>1KB）
- [ ] 多字节字符：中文、emoji、RTL 文字
- [ ] 特殊字符：引号、反斜杠、换行、NULL 字节
- [ ] 时间：时区边界、闰秒、跨夏令时

`fixtures/edge.json`

## 3. 非法（invalid）

- [ ] 类型错误（传 string 给 number）
- [ ] 缺必填字段
- [ ] 格式错误（邮箱没 @、JSON 不完整）
- [ ] 越权输入（尝试访问不属于自己的资源）
- [ ] SQL 注入 / XSS 字符串（即使不该由本模块负责，也要确认它不会崩）

`fixtures/error.json`

## 4. 脏数据（dirty）

这一类来自真实生产，最有价值：

- [ ] 重复记录
- [ ] 部分字段缺失
- [ ] 编码不一致（UTF-8 vs GBK）
- [ ] 上游已废弃但仍在传输的旧字段
- [ ] 顺序不确定的集合

`fixtures/dirty.json`

## 5. 规模（scale）

- [ ] 1k 条
- [ ] 10k 条（暴露 O(n²) 和内存膨胀）
- [ ] 单条超大数据（如 10MB 文件、超长文本字段）

`fixtures/scale.json`

## 失败注入清单

不只是改输入，还要主动打瘜外部依赖：

- [ ] 外部 API 超时
- [ ] 外部 API 返回 500
- [ ] 外部 API 返回畸形 JSON
- [ ] 数据库连接断开
- [ ] 并发：同一实例同时被调用 N 次
- [ ] 幂等：相同入参连续调用两次，结果一致
- [ ] 中断：中途取消

每项都必须断言**错误信息可读**（不能只是拿到 `null`）。

## 断言纪律

- ❌ 禁止 `expect(x).toBeTruthy()` 这种弱化断言
- ❌ 禁止为了让测试变绿而改断言
- ✅ 检查具体值、具体错误类型、具体错误消息
- ✅ 外部调用的断言要同时校验「调了几次」和「传了什么参数」
